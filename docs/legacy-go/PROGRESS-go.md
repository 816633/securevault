第 8 轮把界面现代化，但引入了两个严重回归和一个我自己的递归崩溃。用户反馈：

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 56 | **控件看不见、也点不到**（显示不全 / 点不了） | 第 8 轮新增的滚动裁剪用 `ClearClipRect()` 恢复窗口区域，而它传的是 `CreateRectRgn(0,0,0,0)`（**空区域**）→ 控件被裁成 0 面积。`IsWindowVisible` 仍是 true，所以原有断言全部漏过 | 改为 `SetWindowRgn(hwnd, NULL, …)`；新增断言"没有控件被裁剪成不可见/不可点"（`GetWindowRgn`+`GetRgnBox`） |
| 57 | **窗口四周一圈大黑框** | 双缓冲绘制把 `WM_ERASEBKGND` 关掉了，但重绘只填"内容区"，内容区以外的区域（左右边距、标签条下方、状态栏那一条）从未被绘制 → 未初始化内容显示为黑色 | 重绘时先铺满整个客户区；截图统计黑色像素 4.0% → 0.9% |
| 58 | **点几下崩溃（栈溢出）** | 新写的自绘按钮在 `WM_GETDLGCODE` 里又调了 `dispatchMessage`（就是当前函数）→ 无限递归 → 栈溢出，进程直接消失 | 该分支改为直接返回 `DLGC_BUTTON`；新增"点击压力测试"（逐页点完所有按钮 + 滚轮 + 立即上锁）来持续守住 |

顺带做的加固（都属于"后台工具不该因为 UI 小毛病整体消失"）：

- 窗口过程、托盘/设备消息回调、复制 goroutine、设备事件循环、设备广播窗口过程全部加 `recover()`：单个界面回调的 panic 只写日志，不再结束进程。
- 上锁不再在面板自己的消息处理里 `DestroyWindow`，改为"先隐藏 + 把销毁排到消息队列"。
- 按钮全部改为自绘扁平样式（悬停/按下/禁用/焦点各有状态），用标准子类化 + `CallWindowProc` 交回原窗口过程，`BM_CLICK`、空格/回车、Tab 导航、无障碍行为不变。
- 自绘控件支持 `WM_PRINTCLIENT`，截图工具能拍到按钮/卡片/标签条。

关键新增断言（防止本轮问题回归）：

1. 关掉面板后：界面已锁定、**引擎仍在运行、数据库仍打开、密钥仍在**；
2. 关掉面板后**插入设备仍会真的复制**（真实文件、子目录、中文名、空文件，并写入"已复制"记录）；
3. 关闭"后台监控"后上锁：引擎停止、数据库关闭、密钥清空；
4. **模拟重启**：`Lock()` 后 `autoResumeBackground()` 能在不输密码的情况下恢复后台引擎，且界面仍是上锁的；
5. 逐页、逐列表核对"列宽合计 ≤ 列表宽度"；
6. `scripts\e2e`：用真实窗口消息/按钮点击走完"首次设密 → 恢复码 → 配置目标目录 → 切复制模式 → 关面板（进程仍在）→ 再次运行激活 → 错密码被拒 → 对密码打开面板"。

## 二、已完成的功能（对照 `需求.md` 逐条）

### 交付形态
- ✔ Go 语言后端，**纯 Go 原生 Win32 GUI**（自研 `internal/ui` + `internal/ui/win` 两层）。
- ✔ `CGO_ENABLED=0`、单文件 exe、无外部依赖、不写注册表。
- ✔ 所有数据只写在 **exe 所在文件夹**下的 `SecureVaultData\`（已用运行验证：只生成 `logs\`、`tmp\`、`vault.db`、`keystore.json`）。
- ✔ DPI 自适应：进程声明 Per-Monitor V2，全部坐标走 `ui.S()` 缩放（本机 144 DPI 实测正常）。

### 启动与安全
- ✔ 首次打开先设密码（≥8 位，两次确认）→ 弹出恢复码，**只显示一次**（关闭前二次确认；支持复制/另存 txt）。
- ✔ 恢复码格式 `XXXX-XXXX-XXXX`（大写字母+数字，`crypto/rand` + 拒绝采样；校验忽略大小写与横线）。
- ✔ 密码丢失可用恢复码重置，并**轮换**出新恢复码（旧码立即失效）；两者都丢失则数据无法解密。
- ✔ 打开程序默认不显示窗口，最小化到托盘；托盘标题只有 `SecureVault` 一个。
- ✔ 关闭窗口 = 收进托盘 + **立即上锁**（释放数据库句柄、清空内存密钥、停止引擎）。
- ✔ 再次打开需输入密码；彻底退出必须走托盘「退出程序」并再次验证密码。

- ✔ 连续 5 次密码错误锁定 60 秒，状态持久化（重启依然生效）。

- ✔ 监控模式 / 复制模式 / 关闭，可随时手动切换。

### 第 3 轮：主面板"打开后什么都没有"的根因（已解决）

这一轮把"打开面板一片空白"彻底查清并修掉了，根因有 5 个，全部是真实缺陷：

| # | 根因 | 说明 | 修复 |
|---|---|---|---|
| 35 | 页面容器窗口**缺少 `WS_VISIBLE`** | `NewPage` 里 `style := uint32(WS_CHILD\|...)` 的常量把 `WS_CLIPCHILDREN\|WS_CLIPSIBLINGS` 顶掉了（它们与 `WS_CHILD` 共用位），窗口创建出来就是隐藏的 → 里面的控件全部不可见 | `NewPage` 显式加 `WS_VISIBLE`；`Form.create` 加兜底断言（期望可见却不可见时补一次 `ShowWindow`） |
| 36 | 系统 Tab 控件与页面**互相遮挡** | Tab 控件把整个矩形画成灰底：它盖住页面 → 页面空白；页面盖住它 → 标签看不见。用 `SetWindowRgn` 精密切割也不稳定 | 标签控件只占**标签条那一行**（高度 30 DIP），页面从它下方开始，两者零重叠；去掉嵌套子窗口，页面控件**直接挂主窗口**（向导对话框一直这么做，稳定可见） |
| 37 | 页面控件**没有按页显示/隐藏** | 扁平结构下七个页面的控件会全部叠在一起（实测 140 个控件同时可见，画面完全糊掉） | 新增 `Form.SetControlOwner` + `pageBase.TrackControl` 自动登记；`selectPage` 显示当前页、隐藏其余页；且必须在首次 `layout` **之后**再选页 |
| 38 | 页面标题被登记到**上一个页面** | 归属者在创建标题**之后**才设置，导致"日志页标题"归了"设置页"，切页后标题残留 | `newContainer` 先 `SetControlOwner(b)` 再建标题；`TrackControl` 增加自愈（同一控件若被别的页面登记过就先移除） |
| 39 | 卡片标题控件被**重复创建** | `layout()` 里调用了 `NewCard`，每次布局都多建一个标题并把后续内容往下推 → 控件被推出可视区 | 拆成 `NewCard`（仅在 build 阶段调用一次）与 `LayoutCard`（layout 阶段只重新定位） |
| 40 | 页面布局的**坐标系契约不一致** | 框架把"逻辑矩形"传给 `layout(r)`，而页面代码把它当设备像素用；150% DPI 下算出的坐标直接落到窗口外 | 统一契约：`layout(r)` 的 r 一律是**设备像素**；页面内固定尺寸用 `ui.K()` 换算。状态页的 `ui.ToLogical(r)` 误用已修正 |

### 自动验收覆盖的真实步骤（`-autotest`，写 `SecureVaultData\autotest.log`）
1. 首次设置密码成功；2. 恢复码格式 `XXXX-XXXX-XXXX` 校验；3. 正确密码解锁；4. 取到 32 字节 DEK；
5. 错误密码被拒绝；6. 走真实 `afterUnlock` 流程；7. 数据库打开；8. 引擎启动；9. 主面板创建；
10. 7 个标签页全部构建；11. 逐页切换无卡死；12. 设置写入；13. 模拟设备接入后写入监控记录（0→5 条）；
14. 生效模式判定正确（监控模式）；15. 所有页面容器尺寸正常；16. 窗口客户区尺寸合理（1418×904 @150%）；
17. **所有控件都在页面可视范围内**（防"按钮被挤出窗口"）；18. **没有零尺寸控件**；
19. 上锁后数据库关闭；20. 上锁后引擎停止；21. 上锁后内存密钥清空；22. 用恢复码重置密码成功；
23. 生成新恢复码（与旧码不同）；24. 新密码可用；
25. **用错误的当前密码改密被拒绝**；26. 正确旧密码可改密；27. 改密后密钥未丢；
28. **改密后旧密码失效**；29. **改密后新密码可用**。

> 第 17/18 两项是为了防住"控件被挤出可视区"这类排版 bug 而加的（第 18 项缺陷就是靠人工核算才发现的）；
> 第 25–29 项是为了守住第 17 号缺陷（`ChangePassword` 曾忽略旧密码）不再回归。
