## 二、数据与格式

### 2.1 磁盘布局（全部在 `<程序目录>\SecureVaultData\`）

| 文件 | 说明 |
|---|---|
| `vault.db` | SQLite（WAL）。敏感列是 BLOB 密文，非敏感列明文 |
| `keystore.json` | 密钥库（格式与旧 Go 版一致，见下） |
| `logs\yyyy-mm-dd.txt` | 按天日志，UTF-8 + CRLF |
| `tmp\` | 原子写临时目录 |
| `update\` | 检查更新时下载的压缩包与解包目录（覆盖成功后整目录删除） |
| `legacy-go\` | 检测到旧版数据库时原样搬到这里 |

程序目录里的 `assets\cacert.pem` 是随包分发的 CA 证书包（不是数据，属于程序文件）：
系统证书库缺根证书时用它做 HTTPS 校验。

`SV_DATA_DIR` 环境变量可以覆盖数据目录名，自动化测试用它做隔离。

### 2.2 密钥库格式（与 Go 版完全兼容）

```json
{
  "version": 1,
  "createdAt": "...", "changedAt": "...",
  "kdf": { "algo": "PBKDF2-HMAC-SHA256", "iter": 200000, "salt": "<base64 16B>" },
  "pwdWrap": { "wrapped": "<base64>", "verifier": "<base64>" },
  "recWrap": { "wrapped": "<base64>", "verifier": "<base64>" },
  "failCount": 0, "lockedAt": "", "lockedTill": "",
  "autoUnlock": { "wrapped": "<base64 DPAPI>", "createdAt": "...", "note": "..." }
}
```

- `PBKDF2-HMAC-SHA256(secret, salt, 200000, dklen=64)` → `KEK = 前 32B`，`KMAC = 后 32B`。
- `wrapped = AES-256-GCM(KEK, DEK, AAD)`，AAD 分别是
  `SecureVault|keystore|v1|pwd` 与 `SecureVault|keystore|v1|rec`。
- `verifier = HMAC-SHA256(KMAC, "SecureVault|keystore|v1|pwd|hmac" / "...|rec|hmac")`。
- 恢复码：`XXXX-XXXX-XXXX`，字符集去掉易混淆的 `I O 0 1`；比较时忽略大小写与横线。
- 连续 5 次失败 → 冷却 60 秒（`lockedTill` 落盘，重启依然生效）。

### 2.3 数据库加密

- 字段级 AES-256-GCM：`nonce(12) || ciphertext || tag(16)`，AAD 固定 `SecureVault|field|v1`；
  空串存 `NULL`。
- 加密列：备注、目标目录、盘符、卷标、总线、型号、厂商、VID、PID、USB 序列号、
  磁盘序列号、文件系统、设备实例 ID、卷 GUID、设备路径；名单的值与备注；
  别名的字段值 / 别名 / 备注；计划备注；设置 JSON；增量索引的源路径与目标路径。
- 明文列：时间、事件、动作、各类计数、容量、物理磁盘号、可移动标志（用于 SQL 排序过滤）。
- 关键词搜索：SQL 先按时间 / 事件过滤并 `LIMIT 20000`，解密后在 Python 侧做关键词过滤与分页。
- 增量索引去重：`HMAC-SHA256(HMAC(dek, "…|blind-index"), 路径小写)` 当主键，
  路径明文另存密文列。

### 2.4 表结构

`meta` / `records` / `exclude_rules` / `name_lists` / `aliases` / `schedule` /
`settings_kv` / `file_marks`，建表语句见 `securevault/storage/store.py` 的 `_SCHEMA`。
`meta.schema_version` 用于识别「本程序的数据库」；不认识的库会被搬到 `legacy-go\`。

`file_marks`（增量索引）的**主键是 (device_key, source_key)**：
`device_key` 是设备标识（`sn:<磁盘序列号>` / `sn:<USB 序列号>` / `vg:<卷 GUID>` /
`vol:<卷标>` / `letter:<盘符>`），`source_key` 是 `HMAC(盲索引密钥, device_key|小写路径)`。
这样同一个盘符换一块盘不会互相干扰；老版本（没有 device_key）的表在打开时会被重建
（代价只是下次重新复制一遍）。

### 2.5 密码失败计数策略

`KeyStore.unlock(secret, count_failure=True)` 控制是否累计失败次数：

| 场景 | 计数 | 说明 |
|---|---|---|
| 解锁窗口输密码 | **是** | 连续 5 次 → 冷却 60 秒 |
| 改密码 / 重新生成恢复码 / 退出确认 / 清除记录 / 清除日志 | 否 | `count_failure=False` |
| 用恢复码重置密码 | 是 | 属于"进不去软件"的场景 |

提示文字分级由 `KeyStore.Status.failure_message()` 生成（5 次机会、封禁 5 分钟）：
前 2 次只说"密码错误"，剩 2 次 / 1 次时带上剩余次数与封禁时长。
解锁弹窗里「忘记密码」是**隐藏入口**：密码框为空时连点确定 6 次才出现，10 秒后自动隐藏
（见 `dialogs.PasswordDialog._bump_empty_click`），界面上不写任何提示。

### 2.6 目标文件存在性检查

`CopyEngine(verify_dest_exists=…, verify_dest_action=…)`：增量命中（大小 + 修改时间都没变）时，
如果开启该选项，会先确认 `mark.dest_path` 是否还在：

* 还在 → 正常跳过；
* 不在 → `recopy`（默认）按"需要复制"处理，把文件补回去；`skip` 则保持跳过。

这样即使目标文件夹被误删，再插一次 U 盘也能自动补齐（对应设置页的两个控件）。

### 2.7 内置硬盘规则

`Settings.exclude_internal_disks`（默认 True）由 `Engine.match_exclude()` 优先判定：
非可移动介质且总线不是 USB 的设备视为"内置硬盘"，直接返回一条虚拟的
`ExcludeRule(type="builtin")`。排除名单页把它作为**第一行**展示（`id=0`）：
删除会被拒绝，修改必须点「内置硬盘规则…」→ 先看警告 → 再输密码确认。

### 2.8 每台设备的复制文件夹名（device_folders）

`device_folders(device_key, folder, updated_at)` 记录**每台设备上次用的文件夹名**。
`Engine.resolve_target_folder()` 在每次复制前：

1. 算出"现在该用的名字"（有别名 `<原名>_<别名>`，否则 `<原名>`）；
2. 与记录里的旧名字比较，不同就把旧目录**改名**（新目录已存在则不合并）；
3. 没有记录（老数据 / 第一次）就在目标目录里找 `<原名>` 或 `<原名>_*` 兜底改名；
4. 把新名字写回记录。

所以别名**新增 / 修改 / 删除**三种情况都是改名而不是新建；设备不在线时，
改名会在下次接入（复制前）发生。别名一变就立刻改名则由
`Engine.rename_after_alias_change(old_aliases, new_aliases)` 完成（比较改名前后的名字）。

### 2.9 密码弹窗的隐藏入口

`dialogs.PasswordDialog`：

* `_bump_empty_click()` —— 密码框为空时点确定：**10 秒窗口内**累计 6 次才显示
  「忘记密码」（`CLICK_WINDOW` / `CLICK_LIMIT`），超时重新计数；
* `_show_forgot_temporarily()` —— 显示 10 秒（`SHOW_SECONDS`）后自动隐藏；
* 点了「忘记密码」→ `on_forgot` 回调。解锁弹窗走到"打开面板"，
  退出 / 危险操作确认则走"重置后继续原操作"（`reset_with_recovery(open_panel=False)`）。
* 设置页的「修改密码…」「重新生成恢复码…」用 `show_forgot=True` **直接显示**入口：
  忘记当前密码时走同一个恢复码重置流程（重置即设定新密码 / 新恢复码），不再回到死路。

### 2.10 左侧按钮的排布（忘记密码 + 强制退出）

密码弹窗底部左侧是一个 `left_box` 容器，`_layout_left(show_forgot)` 每次按
`[忘记密码] [强制退出] [额外按钮]` 的顺序整体 `pack_forget()` + 重新 `pack()`。
用重新排布而不是"就地显示"，是因为后者会让临时出现的按钮压到旁边按钮上。

「强制退出」(`App.force_exit_dialog` → `App.force_exit`) 不校验密码：
先 `autostart.disable()` 并同步设置里的 `autostart=False`，再 `quit()`。
它是"忘了密码又打不开软件"的出口，**只在托盘「退出」的密码框里挂出来**
（`App.request_exit` 传 `force_exit="强制退出"`），解锁窗口不传，所以解锁界面没有它。

### 2.11 更新内容的裁剪

发布说明是整篇 Markdown（下载表格、怎么使用、运行环境…），界面只要"本版改了什么"：

* `update.changes_only(text)` —— 找到标题里含「本版主要改动 / 更新内容 / changelog」等关键字
  的那一级标题，取到下一个同级或更高级标题为止；找不到就返回空串（界面再退回整篇）。
* `pages/about.plain_notes(text)` —— 去掉 `#`、`**`、表格分隔行，列表项换成 `·`。

界面用正常字号（`fonts["base"]`）显示，不再是原来的小号等宽字体。

## 三、运行时设计

### 3.1 线程模型

| 线程 | 职责 |
|---|---|
| Tk 主线程 | 全部界面；`root.after(1000)` 轮询队列 + 刷新状态栏 |
| `sv-monitor` | 等触发事件 → 拍设备快照 → 与上次比对 → 产生接入 / 移除事件 |
| `sv-tick` | 每 20 秒重算生效模式（定时切换） |
| `sv-copy` | 一次复制任务（同一时刻只有一个） |
| `sv-devwatch` / `sv-devpoll` | 隐藏窗口消息循环 + 5 秒轮询兜底 |
| `sv-tray` | 托盘图标消息循环（Explorer 重启后自动重加） |

跨线程只通过 `AppContext.ui(callback, *args)` 投递到界面线程执行，
界面绝不从工作线程直接操作控件。

### 3.2 设备事件为什么用「快照比对」

系统广播只用来触发一次「可能有变化」，真正的插拔判定比较两次快照的差集。
好处：不用解析广播结构体、设备没有盘符也不会漏、通知注册失败时轮询照样工作。

### 3.3 上锁语义

| 设置 | 上锁行为 |
|---|---|
| 后台监控 = 开（默认） | 只隐藏面板 + 要求重新输密码；引擎与数据库继续运行 |
| 后台监控 = 关 | 上锁时停引擎、关数据库、清内存密钥 |

「打开面板 / 退出程序 / 改密码 / 看恢复码」在任何设置下都要密码。

**启动时不弹解锁窗口**：`App._open_keystore()` 在密钥库已初始化时先试 DPAPI 自动
解锁 —— 成功就直接 `start_service(show_panel=False)`（后台跑起来、窗口保持隐藏），
失败也照样 `withdraw()` 只驻留托盘。要打开面板只能左键点托盘图标（或再启动一次，
单实例广播会把已有实例叫醒并弹解锁窗口）。首次使用的「首次使用」弹窗不受影响。

### 3.4 单实例

`CreateMutexW("Local\SecureVault_SingleInstance_PY_8F3A21")` + 广播
`RegisterWindowMessageW("SecureVaultActivate_8F3A21")`；
第二个进程广播后以退出码 0 结束，已有实例收到消息就弹出解锁界面（不会出现第二个窗口）。

### 3.5 在线更新

`securevault/system/update.py`（只用标准库）：

1. **检查**：线路默认官方源（`update.DEFAULT_SOURCE = "github"`，界面上的「线路」下拉
   同时决定检查与下载走哪条），
   `GET https://api.github.com/repos/816633/securevault/releases/latest`；
   加速源把完整地址拼在加速域名后面（`https://v4.gh-proxy.org/https://api.github.com/...`）。
   取 `tag_name` 当最新版本号，`version_tuple()` 按数字段比较（`2.4.10 > 2.4.9`）。
2. **选包**：优先附件里带本次版本号的 `*.zip`，其次任意 zip；附件还没上传时按
   `SecureVault-<版本>-win64-portable.zip` 的命名规则推一个。
3. **下载**：分块写 `<数据目录>\update\<包名>.part`，成功后再 `os.replace` 改名，
   避免把半个包当成完整包。
4. **解包**：`stage()` 丢掉压缩包的顶层目录（发布包是 `SecureVault/...`），跳过
   `SecureVaultData*`、`__pycache__`、说明文件，并用 `_safe_target()` 挡住 `../` 越界条目；
   解完必须在最外层看到 `SecureVault.exe`，否则拒绝覆盖。
5. **覆盖**：`apply_staging()` 逐文件复制；直接写失败（被占用 / 只读）就先
   `os.replace` 成 `<文件名>.old-<时间戳>` 让位再写。正在运行的程序本体与已加载的 dll
   在 Windows 上是带 `FILE_SHARE_DELETE` 打开的，改名一定成功 —— 所以更新不需要外部
   更新器，也不需要 cmd / powershell。
6. **收尾**：`App.__init__` 启动时调 `cleanup_backups()` 清掉上次留下的 `.old-*`
   （只读属性会被先去掉）；覆盖成功后删掉整个 `update\` 目录；「立即重启」=
   `quit()` + `os.startfile(新程序)`。

下载源都在 `SOURCES` 一张表里：官方 `github.com`、`v4.gh-proxy.org`
（CloudFlare 优选 IPv4，默认）、`gh-proxy.org`（CloudFlare 全球）。
界面文字与真实域名同源，改地址只需要动这张表。
默认线路是官方源，用户可以在「线路」里换成两个加速节点。

**HTTPS 证书**：`ssl_context()` 优先用随包的 `assets\cacert.pem`（有些电脑系统证书库
缺根证书、或者日期不对，用系统证书库会直接 SSL 校验失败），取不到才退回系统证书库；
`is_ssl_error()` 会认出证书类错误，界面据此多给一个「忽略证书校验重查」的应急按钮
（只影响这一次查询，下载仍然校验证书）。

### 3.6 触屏

* `touch.touch_available()`：`GetSystemMetrics(SM_MAXIMUMTOUCHES) > 0` 且
  `SM_DIGITIZER` 带触摸位（0x04 / 0x10 / 0x40 / 0x80）才算触摸设备；
  结果缓存，`SV_TOUCH=1/0` 可强制覆盖（自动化测试用）。
* `touch.show_keyboard()`：按顺序试 —— ① `ITipInvocation::Toggle`（COM，让系统自己
  显示触摸键盘）→ ② `TabTip.exe` → ③ `osk.exe`。`TabTip` / `osk` 的清单里带
  `uiAccess`，直接 `CreateProcess` 会被系统以错误 740 拒绝，所以 `_launch()` 在
  这种情况下改用 `ShellExecuteW` 让外壳代劳（不弹 UAC、不需要管理员）；
  2 秒内不会重复拉起。`set_enabled()` 对应设置页的开关，
  `widgets.bind_touch_keyboard()` 把输入框的 `<ButtonPress-1>` 接到
  `show_keyboard_for_touch()` 上面 —— **只有触摸/笔点出来的那一下才弹**：
  触摸点击会被系统翻译成鼠标消息，但消息附加信息里带 `0xFF5157xx` 签名
  （`touch.last_input_is_touch()` 用 `GetMessageExtraInfo()` 判断），
  鼠标（含触摸板）点出来的没有这个签名，所以有触摸屏的笔记本插鼠标用不会乱弹键盘；
  程序自己聚焦（`<FocusIn>`）也不再弹。`SV_TOUCH_CLICK=1/0` 可强制，测试用它。
  探测条件放宽成「`SM_MAXIMUMTOUCHES > 0` 或 `SM_DIGITIZER` 带触摸位」——
  有些整机/驱动只报其中一个。`SV_TOUCH=1/0` 可强制，`tools\dev\touch_probe.py`
  用来在真机上排查。
* **手势滚动**在 `widgets.ScrollArea`：把 `<ButtonPress-1>` / `<B1-Motion>` /
  `<ButtonRelease-1>` 绑在**顶层窗口**的 bindtag 上（子控件的事件会冒泡到 toplevel），
  按下时检查指针是否落在本容器里、是否落在"自己要拖动"的控件上
  （`Treeview` / `Scrollbar` / `Text` / 下拉框），移动超过 `DRAG_THRESHOLD` 才进入滑动，
  用 `yview_moveto()` 按像素跟随手指。滑动期间 `widgets._DRAG_SCROLL` 置位，
  `FlatButton` 松手时看到它就**不触发**回调，避免滑页面时误点按钮。
* **里面的东西自己滚，整页不动**：`_on_wheel()` 先用 `_scrollable_under(event.widget)`
  判断指针是不是落在表格 / 文本框上，是就让那个控件自己滚（Tk 的类绑定负责），
  页面不再跟着滚；触屏拖动则由 `enable_touch_scroll()` 处理 —— 它给 `CheckTree.tree`、
  `FlatText.text` 挂上 `<ButtonPress-1>` / `<B1-Motion>` / `<ButtonRelease-1>`，
  只有"这一下是触摸"（`touch.last_input_is_touch()`）才进入滑动状态，
  用 `_scroll_widget_by()` 按像素调 `yview_moveto()`，并在 `<B1-Motion>` 上
  `return "break"` 阻止表格的拖拽划选。鼠标拖动完全不受影响。

## 四、复制引擎

`securevault/copy/copier.py`：

1. **扫描**（单线程、深度优先、迭代式栈）：
   - 跳过重解析点（符号链接 / junction）避免死循环；
   - 过滤：排除名（文件与文件夹，命中文件夹整棵跳过）、排除扩展名、只复制扩展名、
     0 字节、大小上限、隐藏 / 系统属性；
   - 增量：`store.get_mark(源路径)` 的大小与修改时间都一致 → 跳过；
   - 目标解析：优先复用上次写下的目标路径（原地更新），否则按冲突策略
     覆盖 / 改名 `name (1).ext` / 跳过。
2. **空间检查**：待复制总字节 > 目标剩余空间时直接不开始并返回明确错误。
3. **复制**：`ThreadPoolExecutor`（默认 4 线程，上限 16），每文件失败重试 N 次
   （间隔 200ms×次数，可被停止信号打断），成功后写增量索引并保留修改时间。
4. **过程中空间复查**：每 200 个文件复查一次，不足则安全停止（已复制的保持有效）。

任何异常都不会让进程退出：worker 内部异常记一条错误并继续；
引擎层还有一层 `try/finally` 保证 `copying` 标志与忙碌提示被复位。

## 五、界面层约定

- **不用系统原生外观**：`ttk` 只用于 `Treeview` 与 `Scrollbar`（都配置成扁平直角），
  按钮 / 输入框 / 复选框 / 下拉框 / 进度条都是 `tk` 自绘。
- **直角**：所有容器用「外层 Frame 当 1px 边框 + 内层 Frame 当内容」实现，不画圆角。
- **不叠窗、不叠页**：主面板只创建一次并缓存；八个页面放在同一个网格单元里，
  切换时 `grid()` / `grid_remove()`；锁屏与首次设置用完即销毁。
- **不遮挡**：输入框用固定字符宽度（`width=N`），按钮单独成行或成列，不互相覆盖。
- **可滚动**：`ScrollArea` = Canvas + 内嵌 Frame + 细滚动条，鼠标滚轮在指针进入时
  才绑定 `bind_all`，离开解绑；触屏手指拖动见 3.6。
  内容比窗口矮时把 canvas 窗口项拉到窗口高（不留空白带），比窗口高时交给内容自己撑开，
  并在**顶层窗口的 `<Configure>`** 上重新量一次（子控件后加进来也能分到位置、
  滚动区跟着变长）——否则动态展开的内容会一直不显示。
- **DPI**：启动前声明 per-monitor DPI 感知，按 `GetDpiForSystem()/96` 得到缩放，
  `theme.px()` 统一换算像素，`tk scaling` 同步字体；窗口尺寸按工作区裁剪，保证不外溢。
- **命名坑**：自绘控件里不要用 `self._options` —— 那是 `tkinter.Misc` 的内部方法，
  覆盖它会让 `pack` / `grid` 直接报错（这个坑已经踩过一次，改用 `_choices`）。
- **不闪屏的做法**：主窗口创建后立刻 `withdraw()` 并 `attributes("-alpha", 0)`，
  设置几何、建好内容后再 `alpha=1` + `deiconify()`；对话框在 `__init__` 里先
  `withdraw()`，`finish()` 里算好位置再 `deiconify()` + `grab_set()`。
- **窗口形态**：`_apply_window_mode("lock"/"setup"/"panel")` 统一切尺寸与
  `minsize/maxsize/resizable`；锁屏与首次设置是不可缩放的小窗口。
- **页面切换**：八个页面放在同一个 grid 单元格，切页用 `grid()` / `grid_remove()`；
  主面板构造的最后一步会 `tabbar.select(last_page)`，保证一打开就有页面。
- **底部提示**：`widgets.NotifyBar` 是唯一的操作反馈出口；页面里的
  `Page.hint()` 返回 `HintProxy` —— 构造时给的文字是静态说明（留在原位），
  之后 `set_text()` 的内容属于动态反馈，会转发到 NotifyBar。
- **按钮错误必须可见**：`widgets.FlatButton` 捕获的回调异常会交给
  `widgets.BUTTON_ERROR_HOOK`（由 App 设置 → 写日志 + 底部提示）。
  以前异常被 `except: pass` 吞掉，才会出现"点打开文件夹没反应"这种查不出来的问题。
- **老式密码弹窗**：`dialogs.OldStyleDialog` / `PasswordDialog` / `ask_password_old` /
  `ask_text_old` 用纯 tk 原生控件，浅灰底 `#F0F0F0` + 扁平输入框（不是系统的凹入样式）。
  提示文字一律带 `wraplength`，`reveal()` 时按 `winfo_reqheight()` 校正高度，
  长说明不会被窗口右边裁掉。注意：父窗口被 `withdraw()` 时**不要**调用 `transient()`，
  否则弹窗自己也不会显示。
- **窗口居中**：`dialogs.center_window()` 用于弹窗；主窗口每次 `_reveal()` 都会重算居中位置。
- **表格**：`widgets.CheckTree` 提供复选框列（`☐/☑`）、`selectmode="extended"`、
  表头全选、`action_keys()`（优先返回勾选行，其次鼠标选中行）。页面用
  `fill_tree(tree, rows, keys=[业务 id…])` 传业务主键，批量操作按主键执行。

## 七、打包

```powershell
$env:PYINSTALLER_CONFIG_DIR = "$PWD\.build\pyi-config"   # 避免写到 %APPDATA%
python -m PyInstaller --noconfirm --clean --onedir --windowed `
  --name SecureVault --icon assets\securevault.ico `
  --add-data "$PWD\assets;assets" `
  --distpath .build\dist-dir --workpath .build\work-onedir `
  --specpath .build main.py
# 结果拷到 dist\SecureVault\（build.ps1 就是这套流程）
```

注意（都是踩过的坑）：

- `--add-data` 与 `--icon` 的路径要写**绝对路径**（PyInstaller 3.6 会按 `--specpath` 解析相对路径）。
- PyInstaller 3.6 在 Python 3.8 下首次运行会因缓存目录已存在而报 `FileExistsError`，
  用 `PYINSTALLER_CONFIG_DIR` 指到干净目录即可。
- 打包后 `sys.frozen` 为真，`paths.app_dir()` 取 exe 所在目录，数据仍写在 exe 旁边。
- **不要用 `--onefile`**：Tcl 初始化会稳定失败（`Can't find a usable init.tcl`）。
  用 `main.py -diag` 可以看到：解压目录里 `tcl/init.tcl`（24432 字节）与 `tcl/encoding`
  （78 个文件）都在、内容也对，但 `Tcl_Init` 依然返回错误 —— PyInstaller 3.6 的引导程序
  与 Tcl 8.6 在单文件模式下的兼容问题。`main.prepare_frozen_runtime()` 里保留了一段
  「等解压稳定」的逻辑（对老版本 PyInstaller 有用），但无法救 `--onefile`。
- 图标是自绘的 32bpp DIB 多尺寸 ICO（`tools\genicon.py`）。ICO 目录项固定 16 字节，
  写错会让 `UpdateResource` 报 `(87, 'UpdateResource', '参数错误')`。

## 八、已知技术债

1. 只支持浅色主题，没有主题切换。
2. 复制冲突策略、并发数、重试次数在代码里可配，界面暂未暴露。
3. `records` 关键词搜索是「解密后过滤」，记录量很大时（>2 万条）分页会变慢；
   已用 `LIMIT 20000` 保护。
4. `uicheck` 的截图依赖 PrintWindow，在无桌面会话里会失败（那时几何审计仍可用）。
5. 测试是脚本式断言（自研小框架），没有接 pytest；如需 CI 可直接用这三个脚本的退出码。
6. 在线更新只做整包覆盖，没有差分（增量）更新；包本体约 15 MB。
7. 覆盖更新要求新包里有 `SecureVault.exe`，也要求程序目录可写；放在受保护目录
   （如 `C:\Program Files`）时需要管理员权限，否则会逐个文件报失败。
8. 触屏键盘依赖系统组件 `TabTip.exe` / `osk.exe`；两者都被裁剪过的精简系统上只会有
   提示，不会影响其它功能。
